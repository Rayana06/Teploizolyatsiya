# Лабораторная работа №2

**Задание:** Создание базы данных `PostgreSQL` по теме работы, подключение БД к созданным трём шаблонам.

## PostgreSQL и TypeORM

**Тема:** оценка эффективности теплоизоляции здания. Услуга — карточка изоляционного материала.

Приложение использует NestJS, серверные Handlebars-шаблоны, PostgreSQL 17 и TypeORM. Реализованы ровно шесть HTTP-обработчиков: три GET; POST создания и POST публикации через ORM; POST логического удаления параметризованным SQL `UPDATE` через `QueryRunner`.

## Первый запуск

1. Создайте `.env` по образцу `.env.example`. Если `.env` остался от лабораторной №1, значения PostgreSQL можно не добавлять — используются локальные значения по умолчанию.
2. Запустите `docker compose up -d`.
3. Выполните `npm install`, затем `npm run build` и `npm start`.
4. При первом старте TypeORM автоматически применит миграцию структуры.
5. Откройте Adminer: `http://localhost:8080`. Система — PostgreSQL; сервер — `insulation-postgres`; пользователь, пароль и БД — `teploshchit` (либо значения из `.env`).
6. В Adminer откройте «SQL-команда» и выполните файл `database/adminer-seed.sql`. Так данные будут внесены именно через Adminer, как требует задание.
7. Откройте приложение: `http://localhost:3000/insulation-materials/catalog`.

MinIO лабораторной №1 остаётся источником медиа существующих карточек. Если URL пуст или изображение не загрузилось, чистая HTML-конструкция `<object><img></object>` показывает локальный файл SSR-сервера; для видео в разметке указан второй `<source>`. Оба файла лежат в `public/default-media`. Выбранные в форме новые файлы не имеют атрибута `name`, поэтому браузер не включает их в запрос.

## Структура материалов для защиты

- `database/adminer-seed.sql` — первоначальное заполнение через Adminer.
- `database/defense-queries.sql` — готовые UPDATE/SELECT для требуемых скриншотов.
- `docs/lab2/ER-DIAGRAM.md` — таблицы, типы, длины, PK/FK и связи для переноса в StarUML.
- `docs/lab2/insulation-database.mdj` — готовый проект ER-диаграммы StarUML.
- `docs/lab2/DEFENSE.md` — порядок 22 скриншотов.
- `docs/lab2/CONTROL-QUESTIONS.md` — краткие ответы на контрольные вопросы.

## Проверка

При работающем PostgreSQL выполните `npm test`. Тесты проверяют схему, запрет каскадного удаления, единственность черновика, три страницы, медиа по умолчанию и полный цикл ORM/SQL.
