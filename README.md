# Лабораторная работа №3

## Описание REST-методов

| Метод | URL | Описание |
|---|---|---|
| GET | `/api/insulation-materials` | Возвращает список опубликованных услуг. Поддерживает фильтрацию по максимальной толщине, типу утеплителя и названию. Поле `isCreator` показывает, создана ли услуга текущим пользователем: `1` — создана, `0` — создана другим пользователем. |
| GET | `/api/insulation-materials/feed` | Возвращает первый опубликованный элемент ленты. Используется, когда у клиента ещё нет идентификатора текущего элемента. |
| GET | `/api/insulation-materials/feed/:id?next=true` | Возвращает следующий опубликованный элемент ленты после услуги с указанным идентификатором. Поле `liked` показывает наличие лайка текущего пользователя, а `likeCount` — общее количество лайков. |
| GET | `/api/insulation-materials/draft` | Возвращает единственный черновик текущего пользователя. Идентификатор услуги в запросе не передаётся. Если черновика нет, возвращается `null`. |
| POST | `/api/insulation-materials` | Создаёт новую услугу со статусом `draft`. Данные отправляются как `multipart/form-data`. Изображение и видео передаются файлами и сохраняются в MinIO, а их имена сохраняются в базе данных. |
| PUT | `/api/insulation-materials/:id/publish` | Публикует черновик текущего пользователя. Статус услуги изменяется с `draft` на `published`, заполняется дата публикации. |
| DELETE | `/api/insulation-materials/:id` | Выполняет логическое удаление услуги текущего пользователя. Запись остаётся в базе данных, её статус изменяется на `deleted`, заполняется дата завершения. |
| POST | `/api/insulation-materials/:id/like` | Устанавливает или отменяет лайк текущего пользователя. Значение `liked: 1` создаёт лайк, значение `liked: 0` удаляет лайк. |
| POST | `/api/users/register` | Регистрирует нового пользователя. Принимает электронную почту, отображаемое имя и пароль. В базе данных сохраняется хеш пароля, а не открытый пароль. |
| POST | `/api/users/authenticate` | Заглушка аутентификации, подготовленная для лабораторной работы №4. |
| POST | `/api/users/logout` | Заглушка деавторизации, подготовленная для лабораторной работы №4. |

## Описание таблиц базы данных

### Таблица `users`

Хранит зарегистрированных пользователей системы.

| Поле | Тип | Описание |
|---|---|---|
| `user_id` | `serial` | Первичный ключ пользователя |
| `email` | `varchar(254)` | Адрес электронной почты; обязательное и уникальное поле |
| `display_name` | `varchar(100)` | Отображаемое имя пользователя |
| `password_hash` | `varchar(255)` | Хеш пароля с солью; открытый пароль не хранится |

### Таблица `insulation_materials`

Хранит услуги — теплоизоляционные материалы.

| Поле | Тип | Описание |
|---|---|---|
| `insulation_material_id` | `serial` | Первичный ключ услуги |
| `name` | `varchar(120)` | Название услуги |
| `short_description` | `varchar(300)` | Краткое описание |
| `status` | `enum` | Статус услуги: `draft`, `published` или `deleted` |
| `image_url` | `varchar(500)` | Имя объекта изображения в MinIO |
| `video_url` | `varchar(500)` | Имя объекта видео в MinIO |
| `insulation_type` | `varchar(50)` | Тип утеплителя |
| `thickness_mm` | `smallint` | Толщина материала в миллиметрах |
| `created_at` | `timestamptz` | Дата и время создания |
| `published_at` | `timestamptz` | Дата и время публикации |
| `completed_at` | `timestamptz` | Дата и время логического удаления |
| `creator_id` | `integer` | Внешний ключ на создателя из таблицы `users` |
| `moderator_id` | `integer` | Внешний ключ на модератора из таблицы `users`; может быть пустым |

Для одного пользователя допускается не более одного черновика.

### Таблица `insulation_material_likes`

Хранит информацию о том, какой пользователь поставил лайк какой услуге.

| Поле | Тип | Описание |
|---|---|---|
| `insulation_material_like_id` | `serial` | Первичный ключ записи о лайке |
| `user_id` | `integer` | Внешний ключ на пользователя из таблицы `users` |
| `insulation_material_id` | `integer` | Внешний ключ на услугу из таблицы `insulation_materials` |

Комбинация `user_id` и `insulation_material_id` является уникальной. Поэтому один пользователь не может поставить несколько лайков одной услуге.
