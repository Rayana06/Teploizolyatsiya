# Лабораторная 1: сценарий показа Теплощита

Это план показа и репетиции. Комплект скриншотов 1–19 собран отдельно. Распределение кадров согласовано с порядком из задания.

## Перед показом

1. Запустить Docker Desktop, убедиться, что контейнер MinIO работает. Открыть консоль `http://localhost:9011` и бакет `insulation-materials`. Не включать пароль в скриншоты.
2. Запустить приложение по инструкции `insulation-backend/README.md`. Открыть `http://localhost:3000/insulation-materials/catalog`.
3. Открыть файл Figma с тремя актуальными макетами, сайт-референс и GitHub с веткой `lab1`.
4. Открыть отдельный файл скриншотов, реальные конспекты лекций и письменные ответы. Если были замечания преподавателя — отдельный файл с каждым замечанием, объяснением исправления и подтверждающим скриншотом.

В Network выбирать запрос документа страницы, а не запрос CSS или видео. В Response виден HTML, полученный от сервера. Elements показывает текущий DOM — это другая вкладка и она не заменяет требуемый Response. Если карточки не обновляются из-за кеша, перезагрузить страницу с открытой вкладкой Network; не рисовать строки запросов вручную.

## Вопросы преподавателя по коду

### 1. Покажите код кнопки «Следующий материал»

Сначала показать ссылку в `views/insulation-material-feed.hbs`:

```hbs
href="/insulation-materials/feed/{{insulation.insulationId}}?next=true"
```

Затем показать в `src/insulation-materials/insulation.controller.ts` строку:

```ts
insulationIndex = (insulationIndex + 1) % publishedInsulation.length;
```

Сказать: «Ссылка передаёт ID текущего материала и параметр `next=true`. Контроллер находит текущую позицию среди опубликованных материалов и переходит к следующей. Остаток от деления возвращает ленту к первому материалу после последнего».

### 2. Покажите код подсчёта лайков

Показать в методе `presentInsulation`:

```ts
insulationLikeCount: insulation.insulationLikes.length,
```

Сказать: «У материала хранится вложенный массив лайков с ID пользователей. Контроллер считает длину массива и передаёт готовое число в шаблон. В первой лабораторной лайки не изменяются».

### 3. Объясните структуру проекта

Показывать сверху вниз:

1. `src` — запуск приложения, модуль, контроллер и коллекция материалов.
2. `views` — три Handlebars-шаблона и общие части интерфейса.
3. `public` — отдельный файл CSS.
4. `media/generated` — изображения, постеры и вертикальные видео для MinIO.
5. `scripts` — подготовка и загрузка медиа.
6. `test` — HTTP-проверки.
7. `compose.yaml` — запуск MinIO в Docker.

Связать структуру с MVC: коллекция — модель, шаблоны — представление, контроллер — контроллер.

## Короткая репетиция поведения

| Действие | Ожидаемый результат |
| --- | --- |
| Открыть каталог без параметра | Шесть материалов, ползунок на 1600 ₽/м² |
| Установить 322.21 и нажать «Подобрать» | Два материала |
| Установить 322.22 и нажать «Подобрать» | Четыре материала; равная границе цена включается |
| Установить 0 и нажать «Подобрать» | Пустой результат и ссылка возврата |
| Открыть `/feed/3?next=true` с префиксом `/insulation-materials` | Материал ID 4 |
| Открыть `/feed/6?next=true` с тем же префиксом | Возврат к первому опубликованному материалу |
| Открыть `/feed/7` с тем же префиксом | 404: черновик не публикуется в ленте |
| Нажать «Выбрать файл» под изображением или видео | Открывается системный выбор файла; отправки на сервер нет |
| Изменить поле черновика и перезагрузить страницу | Исходное значение восстановлено, кнопки сохранения нет |
| Нажать «Больше» | Описание раскрывается без клиентского JavaScript |
| Изменить ширину окна | Фиксированная композиция остаётся прежней |

Две марки RAFINAD имеют одинаковую подтверждённую цену, но разные артикулы и назначение. Подробные расчёты и источники — в `design/MATERIAL-SOURCES.md`. Не объясняй совпадение цен тем, что это один товар.

Теорию для подготовки см. в `defense/LAB1-THEORY.md`. Этот сценарий не заменяет личную способность объяснить код на защите.
