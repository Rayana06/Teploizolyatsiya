# Теплощит: подготовка к письменной защите лабораторной 1

Материал для самостоятельной подготовки по работающему приложению. Это не конспект прошедших лекций и не подтверждение сдачи. Примеры соответствуют файлам проекта на 14.09.2026.

## Что сказать о своей работе

«Моя тема — оценка эффективности теплоизоляции здания. В первой лабораторной я реализую просмотр изоляционных материалов: ленту, черновик и каталог. Сервер написан на TypeScript с NestJS, HTML формирует Handlebars. Данные находятся в одной коллекции в памяти, изображения и видео — в MinIO. В каталоге шесть опубликованных материалов. Расчёт теплопотерь и сохранение заявок относятся к следующим этапам».

Не заучивай фразу без понимания: покажи каждый упомянутый компонент в проекте.

## 1. MVC: компоненты в нашем приложении

MVC — разделение ответственности на модель, представление и контроллер.

| Компонент | Обязанность | Где у нас |
| --- | --- | --- |
| Model | Описывает данные предметной области | `src/insulation-materials/insulation-materials.collection.ts`: интерфейс и массив материалов |
| View | Показывает переданные данные | Три файла `views/insulation-material-*.hbs`, общие фрагменты в `views/partials` |
| Controller | Обрабатывает запрос, выбирает данные и представление | `src/insulation-materials/insulation.controller.ts` |

Модель не обязана быть таблицей БД. В лабораторной 1 база данных не используется. Фильтрация реализована в контроллере, что видно в `getInsulationCatalog`.

`insulation.module.ts` регистрирует контроллер в приложении. `main.ts` создаёт приложение, подключает каталог шаблонов, движок `hbs`, общие фрагменты и раздачу CSS. Эти файлы не являются отдельными страницами.

## 2. MVT и отличие терминов

MVT означает Model–View–Template. Model отвечает за данные; View в этой терминологии обрабатывает запрос и выбирает данные; Template задаёт разметку ответа. По обязанностям MVT View ближе к MVC Controller, а MVT Template — к MVC View. Маршрутизацию и часть управления берёт на себя фреймворк.

В нашей реализации использованы названия NestJS: Controller и шаблоны Handlebars. Не называй файл `.hbs` контроллером и не говори, что мы используем Django: он не установлен и не выбран для курса.

## 3. Шаблонизация

Шаблонизация — формирование документа из шаблона и данных. У нас она выполняется на сервере. Браузер получает готовый HTML, а не TypeScript и не исходный `.hbs`.

Пример из каталога:

```hbs
{{#each insulationMaterials}}
  <h2>{{insulationName}}</h2>
  <strong>{{insulationPriceLabel}} ₽/м²</strong>
{{/each}}
```

`each` повторяет разметку для каждого переданного материала. `{{insulationName}}` подставляет значение с HTML-экранированием. `{{#if ...}}` выбирает условный фрагмент. `{{> insulation-tabs}}` подключает общий фрагмент навигации. Частичные шаблоны позволяют не копировать одинаковую разметку в три файла.

Декоратор `@Render('insulation-material-catalog')` выбирает шаблон. Объект, который возвращает метод контроллера, становится его данными. Настройка `app.setViewEngine('hbs')` находится в `main.ts`.

## 4. HTTP и разбор URL

HTTP — протокол прикладного уровня с обменом запросами и ответами. Запрос содержит метод, адрес ресурса, заголовки и, при необходимости, тело. Ответ содержит статус, заголовки и, при необходимости, тело. Успешный запрос страницы возвращает статус 200 и HTML. Несуществующий материал в нашем приложении возвращает 404.

Пример:

```text
http://localhost:3000/insulation-materials/catalog?insulationMaxPrice=322.22
```

| Часть | Значение |
| --- | --- |
| `http` | Схема обращения |
| `localhost` | Компьютер, на котором открыт браузер |
| `3000` | Порт нашего сервера |
| `/insulation-materials/catalog` | Путь каталога |
| `insulationMaxPrice=322.22` | Параметр максимальной цены за м² |

`GET` запрашивает представление ресурса. Форма фильтра использует GET: условие появляется в адресе и может быть повторено. GET не должен сохранять новый материал. В нашей лабораторной обработчиков сохранения нет.

HTTP сам по себе не хранит состояние сеанса между запросами. Состояние может поддерживаться приложением, например с помощью cookies; авторизация в этой лабораторной ещё не реализована. Не утверждай, что HTTP вообще не может использовать cookies.

### Три обработчика

| Пример адреса | Метод контроллера | Результат |
| --- | --- | --- |
| `/insulation-materials/feed/3` | `getInsulationFeed` | Материал с ID 3 |
| `/insulation-materials/feed/3?next=true` | Тот же `getInsulationFeed` | Следующий опубликованный материал, ID 4 |
| `/insulation-materials/feed` | Тот же `getInsulationFeed` | Первый опубликованный материал |
| `/insulation-materials/draft` | `getInsulationDraft` | Единственный черновик из коллекции |
| `/insulation-materials/catalog` | `getInsulationCatalog` | Все опубликованные материалы |

Примеров адресов больше трёх, но GET-обработчиков именно три. CSS, изображения и видео загружаются отдельными техническими запросами. Поэтому в Network будет больше трёх строк — это нормально.

## 5. HTTP и модель OSI

OSI — модель из семи уровней для описания сетевого взаимодействия. Это модель, а не перечень установленных программ.

| № | Уровень | Основная задача |
| --- | --- | --- |
| 7 | Прикладной | Сетевые протоколы приложений; здесь рассматривают HTTP |
| 6 | Представления | Формат и преобразование представления данных |
| 5 | Сеансовый | Организация сеансов взаимодействия |
| 4 | Транспортный | Передача между процессами, например TCP или UDP |
| 3 | Сетевой | Адресация и маршрутизация пакетов, например IP |
| 2 | Канальный | Передача кадров в пределах канала связи |
| 1 | Физический | Передача сигналов через физическую среду |

HTTP/1.1 и HTTP/2 обычно работают поверх TCP; HTTPS добавляет защиту TLS. HTTP/3 использует QUIC поверх UDP. Не говори, что любая версия HTTP всегда использует TCP. В локальном приложении адрес начинается с `http://`, защита HTTPS здесь не настроена. При обращении к `localhost` используется сетевой стек компьютера, но физическая передача по внешней сети не требуется.

## 6. Web и HTML

Web — система связанных ресурсов, доступных по адресам URL через веб-технологии. Интернет — сетевая инфраструктура, Web — один из способов её использования. Наш сайт работает и локально: внешний интернет не нужен для уже загруженных в MinIO материалов.

HTML — язык разметки документа. Он задаёт структуру и смысл элементов: заголовки, ссылки, формы, изображения и видео. CSS отвечает за оформление. JavaScript может добавлять поведение, но клиентского JavaScript в нашей лабораторной нет.

Примеры в приложении: `<a>` переводит на страницу материала; `<form method="get">` отправляет фильтр; `<input type="range">` задаёт максимальную цену; `<input type="file">` открывает системный выбор файла; `<img>` показывает изображение; `<video>` воспроизводит ролик; `<details><summary>` раскрывает описание без JavaScript. Атрибут `alt` задаёт текстовую альтернативу изображению.

## 7. Объяснение своего фильтра

Последовательность в `getInsulationCatalog`:

1. `@Query('insulationMaxPrice')` получает строку из URL.
2. Сервер проверяет число в диапазоне от 0 до 1600 ₽/м²; точка и запятая допустимы как разделитель.
3. Без параметра используется 1600 ₽/м², поэтому отображаются все шесть опубликованных материалов.
4. Из коллекции выбираются только опубликованные материалы с ценой не выше ограничения.
5. `presentInsulation` подготавливает адреса медиа, цену для отображения и количество лайков.
6. Контроллер возвращает массив и выбранное значение шаблону. Поэтому положение ползунка сохраняется после GET-запроса.

Без клиентского JavaScript браузер не может выводить произвольное текущее число при каждом пикселе движения ползунка. Поэтому интерфейс показывает постоянную шкалу с реальными ценовыми отметками, а точное выбранное значение подтверждает сервер после нажатия «Подобрать». Это сохраняет обязательный для лабораторных 1–4 запрет клиентского JavaScript.

Ключевая строка из проекта:

```ts
const foundInsulation = insulationFilterError ? [] : insulationMaterials.filter(
  material => material.insulationStatus === 'published'
    && material.insulationPriceRubM2 <= insulationPriceLimit
);
```

Проверка в браузере не заменяет серверную проверку: URL можно изменить вручную. `filter` создаёт новый массив выбранных элементов, исходную коллекцию он не удаляет и не сокращает.

## 8. Лента, лайки и MinIO

В `getInsulationFeed` сначала отбираются опубликованные материалы. `findIndex` ищет позицию материала по ID. ID и индекс — разные понятия: ID 3 в текущем массиве опубликованных материалов имеет индекс 2. Для `next=true` используется `(insulationIndex + 1) % publishedInsulation.length`; после последнего материала открывается первый. Черновик и удалённый материал пропускаются.

Число лайков вычисляется в `presentInsulation`: `insulation.insulationLikes.length`. Лайки демонстрационные; кнопка не изменяет их. Вложенная коллекция ID пользователей разрешена заданием. Остальные характеристики материала — отдельные значения, не массивы вариантов.

MinIO хранит объекты: файл лежит в бакете под ключом. В коллекции отдельные поля `insulationImageKey` и `insulationVideoKey`. Контроллер составляет URL, например `http://localhost:9010/insulation-materials/technolight-optima-50.mp4?v=5`. Порт 9010 обслуживает объекты, 9011 — интерфейс управления. Параметр `v=5` позволяет обновлять кешируемые медиа при смене файлов.

Браузер получает HTML с адресами медиа, затем самостоятельно запрашивает эти адреса. NestJS не встраивает содержимое MP4 в HTML. Атрибуты `autoplay muted playsinline` задают автозапуск без звука и воспроизведение внутри страницы; политика браузера всё же может ограничить автозапуск. `poster` — изображение до начала воспроизведения, не сам ролик.

## 9. Дополнительные вопросы, которые преподаватель задавал на защите

### Как реализована кнопка «Следующий материал»?

В шаблоне `views/insulation-material-feed.hbs` кнопка является обычной HTML-ссылкой. Клиентский JavaScript не используется:

```hbs
<a class="insulation-next"
   href="/insulation-materials/feed/{{insulation.insulationId}}?next=true"
   aria-label="Следующий материал">
  <strong aria-hidden="true">→</strong><span>Следующий</span>
</a>
```

В адрес передаются ID текущего материала и query-параметр `next=true`. Один обработчик `getInsulationFeed` получает их через `@Param` и `@Query`. Сначала он оставляет только опубликованные материалы, затем находит индекс текущего материала и увеличивает его на единицу:

```ts
if (next === 'true' && insulationId !== undefined) {
  insulationIndex = (insulationIndex + 1) % publishedInsulation.length;
}
```

Оператор `%` зацикливает ленту: после последнего опубликованного материала открывается первый. Это не четвёртый маршрут, а другой режим того же GET-обработчика.

### Как считается количество лайков?

В каждой записи материала есть вложенный массив `insulationLikes`, содержащий ID пользователей:

```ts
insulationLikes: Array.from(
  { length: 24 },
  (_, i) => ({ insulationReaderId: i + 1 }),
)
```

Перед передачей материала в шаблон метод `presentInsulation` вычисляет количество элементов массива:

```ts
insulationLikeCount: insulation.insulationLikes.length,
```

В Handlebars выводится уже готовое число:

```hbs
<div class="insulation-feed-likes"><span>♡</span><strong>{{insulation.insulationLikeCount}}</strong></div>
```

Так выполняется требование считать лайки по коллекции в контроллере. В лабораторной №1 лайки только отображаются и не изменяются.

### Как устроена структура проекта?

Главные части проекта распределены по назначению:

```text
insulation-backend/
├── src/
│   ├── main.ts
│   └── insulation-materials/
│       ├── insulation.module.ts
│       ├── insulation.controller.ts
│       └── insulation-materials.collection.ts
├── views/
│   ├── insulation-material-feed.hbs
│   ├── insulation-material-draft.hbs
│   ├── insulation-material-catalog.hbs
│   └── partials/
├── public/insulation-materials.css
├── media/generated/
├── scripts/
├── test/
└── compose.yaml
```

- `main.ts` запускает NestJS, подключает Handlebars, общие части шаблонов и статический CSS.
- `insulation.module.ts` регистрирует контроллер предметной области.
- `insulation.controller.ts` содержит три GET-обработчика, выбор материалов, подсчёт лайков, формирование URL MinIO и фильтрацию.
- `insulation-materials.collection.ts` содержит интерфейс материала и единственную коллекцию без базы данных.
- `views` содержит три предметных шаблона и общие части интерфейса.
- `public` содержит вынесенный CSS.
- `media/generated` содержит подготовленные изображения, постеры и вертикальные видео, которые загружаются в MinIO.
- `scripts` содержит подготовку медиа и заполнение бакета MinIO.
- `test` содержит HTTP-проверки трёх страниц и фильтрации.
- `compose.yaml` описывает контейнер MinIO.

С точки зрения MVC коллекция выполняет роль модели, Handlebars-шаблоны — представления, а `InsulationController` — контроллера.

## 10. Тренировка на 10 минут

Закрой код и попробуй письменно:

1. Нарисовать цепочку: браузер → маршрут NestJS → коллекция → Handlebars → HTML → браузер; отдельно отметить запросы браузера в MinIO.
2. Написать префикс `@Controller('insulation-materials')`, декораторы `@Get('catalog')`, `@Render('insulation-material-catalog')` и параметр `@Query('insulationMaxPrice')`.
3. Написать условие фильтра опубликованных материалов по максимальной цене.
4. Показать цикл Handlebars, выводящий название и цену.
5. Объяснить, почему URL с `next=true` не добавляет четвёртый обработчик.
6. Написать ссылку кнопки «Следующий материал» и строку изменения индекса.
7. Написать подсчёт лайков через `insulation.insulationLikes.length`.
8. Нарисовать структуру проекта и назвать назначение `src`, `views`, `public`, `media`, `scripts` и `test`.

После этого сравни с исходниками. Хороший критерий готовности — ты можешь объяснить каждую строку своими словами и предсказать результат для цены 322.21 и 322.22: сейчас это два и четыре материала соответственно.
