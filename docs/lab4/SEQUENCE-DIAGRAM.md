# Sequence-диаграмма лабораторной №4

Основной редактируемый файл: `teploshchit-lab4.mdj`. Он содержит две связанные UML-диаграммы:

1. `Диаграмма классов API — ЛР4` — классы доменов и их операции.
2. `Sequence — полный бизнес-процесс ЛР4` — восемь HTTP-запросов из задания.

## Lifeline

- `client: SPAClient` — браузерный SPA-клиент;
- `usersApi: UsersAPI` — домен `/api/users`;
- `materialsApi: InsulationMaterialsAPI` — домен `/api/insulation-materials`.

База данных, Redis, MinIO и нативное приложение намеренно отсутствуют: по условию sequence-диаграмма показывает HTTP-бизнес-процесс без БД и нативного приложения.

## Сообщения

1. `authenticate(email, password)` — аутентификация, в ответе пользователь и cookie `sessionId`.
2. `list(maxThicknessMm, insulationType)` — список услуг с фильтром.
3. `create(fields, image, video)` — создание услуги-черновика с изображением и видео.
4. `draft(sessionId)` — получение полей своего черновика.
5. `publish(id, sessionId)` — публикация услуги.
6. `feed()` — первый элемент ленты без `id`.
7. `feed(id, next=true)` — следующий элемент ленты; это перегрузка той же операции.
8. `setLike(id, liked=true, sessionId)` — установка лайка.

## Что показать преподавателю в StarUML

1. Открыть `teploshchit-lab4.mdj`.
2. В Model Explorer открыть `Sequence — полный бизнес-процесс ЛР4`.
3. Выбрать любое сообщение-запрос, например `publish(...)`.
4. В Property Editor показать свойство `signature`: оно ссылается на операцию `publish` класса `InsulationMaterialsAPI`.
5. Открыть `Диаграмма классов API — ЛР4` и показать ту же операцию в классе.

Для снимка №9 лучше выбрать `publish(...)`: имя короткое, а связь с методом класса хорошо видна.

> Если подпись сообщения редактировать вручную, совпадение текста не доказывает переиспользование. Нужна именно заполненная ссылка `signature`.
