# Порядок показа — 22 скриншота

1. Adminer: `UPDATE insulation_materials SET status='deleted' ...`.
2. Adminer: `SELECT` со статусом `deleted`.
3. Лента опубликованного материала.
4. Каталог до поиска.
5. Результат поиска по максимальной цене.
6. Каталог с кнопкой «Удалить».
7. Результат логического удаления: карточка пропала.
8. Прямой URL удалённой услуги: HTTP 404.
9. Страница добавления без черновика: название, фото, видео, «Далее».
10. Созданный заполненный черновик с кнопкой «Опубликовать».
11. Adminer: `SELECT` показывает новый статус `draft`.
12. Опубликованная карточка в приложении.
13. Adminer: `SELECT` показывает `published` и `published_at`.
14. Adminer: изменение `insulation_type`, `thickness_mm` и вставка строки в M:N.
15. Adminer: агрегирующий `SELECT` с новым количеством лайков.
16. Приложение: изменённые тип, толщина и количество лайков.
17. Модель `User`.
18. Модель `InsulationMaterial`.
19. Модель `InsulationMaterialLike` и внешние ключи `RESTRICT`.
20. Три GET-обработчика через ORM.
21. Два POST через ORM и POST удаления с SQL `UPDATE`/`QueryRunner`.
22. HTML: локальные `default-insulation.jpg` и второй `<source>` `default-insulation.mp4`.

Формулировка задания нумерует блоки 1–22, но перечисляет внутри них больше отдельных действий. Этот порядок объединяет связанные кодовые фрагменты в один кадр, чтобы сохранить ровно 22 изображения.
