# Контрольные вопросы — ЛР5

## Что такое React?

React — библиотека для декларативного построения пользовательских интерфейсов из компонентов. Разработчик описывает желаемый UI для текущих данных, а React обновляет только необходимые части DOM.

## Чем props отличаются от состояния?

`props` — входные неизменяемые данные, которые родитель передаёт дочернему компоненту. Состояние (`state`) принадлежит компоненту, может меняться через setter и вызывает повторный рендер. В проекте `CatalogFilters` получает значения и обработчики через props, а сами значения хранятся в state страницы `CatalogPage`.

## Чем компонент отличается от элемента?

Компонент — функция или класс, описывающие повторно используемую часть интерфейса. React-элемент — обычный неизменяемый объект, результат JSX, который сообщает React, что следует отобразить. Вызов `<MaterialCard material={...} />` создаёт элемент компонента `MaterialCard`.

## Что делают useState и useEffect?

`useState` добавляет функциональному компоненту состояние и возвращает пару «текущее значение — функция обновления». `useEffect` выполняет побочный эффект после рендера. Массив зависимостей определяет моменты повторного запуска; возвращённая функция выполняет очистку перед следующим эффектом или размонтированием.

## Каков жизненный цикл компонента?

Три основные стадии: монтирование, обновление и размонтирование. Функциональный компонент рендерится при монтировании, повторно рендерится при изменении props/state и удаляется при размонтировании. `useEffect` объединяет действия для этих стадий: эффект после рендера и cleanup перед повтором/удалением.

## Что такое Vite и Babel?

Vite — инструмент разработки и сборки: быстро запускает dev-сервер, использует нативные ES-модули и создаёт production-сборку через Rollup. Babel — транспилятор JavaScript/JSX, преобразующий современный синтаксис под выбранные браузеры. В этом проекте React-плагин Vite обрабатывает JSX через современный быстрый трансформер; отдельный Babel-конфиг не нужен. TypeScript проверяет типы, но сам по себе не является заменой всей цепочки сборки.

## Зачем нужен useMemo?

`useMemo` запоминает результат вычисления между рендерами и повторяет его только при изменении зависимостей. Здесь mock-коллекция повторно фильтруется по максимальной цене только после изменения применённой цены кнопкой «Подобрать».

## Зачем нужен useRef?

`useRef` хранит изменяемую ссылку между рендерами, но изменение `current` не запускает новый рендер. В `MaterialMedia` ссылки нужны для управления HTML-элементом `video`, полноэкранным контейнером и плавной браузерной анимацией увеличения.

## Почему нет Redux и Context?

Задание прямо запрещает Redux и Context. Для небольшого SPA достаточно локального состояния страницы и передачи данных/обработчиков через props.

## Как реализовано медиа по умолчанию?

Компонент `MaterialMedia` выбирает локальный файл, если URL пустой. Отдельные состояния `imageFailed` и `videoFailed` переключают источник на fallback также при событии ошибки загрузки. Файлы лежат внутри проекта, поэтому решение не зависит от внешнего сервера.
